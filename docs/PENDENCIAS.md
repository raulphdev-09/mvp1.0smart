# Pendências para aprovação e publicação

Este projeto é um protótipo comercial não oficial. As categorias e o fluxo demonstrativos precisam ser confirmados antes de virar conteúdo institucional. Não preencher lacunas com dados fictícios.

## Identidade e conteúdo

- [ ] Confirmar o nome comercial e autorizar o uso da marca no site.
- [ ] Fornecer logotipo autorizado, se houver; não copiar marcas de terceiros.
- [ ] Aprovar o texto institucional em `aboutText`.
- [ ] Informar os serviços efetivamente prestados e aprovar suas descrições em `services`.
- [ ] Confirmar as etapas reais de atendimento em `process`.
- [ ] Fornecer fotografia real de dispositivo em reparo para `heroPhoto`, com autorização de uso.
- [ ] Fornecer fotografia real da fachada ou ambiente para `aboutPhoto`, com autorização de uso.
- [ ] Revisar textos alternativos e enquadramento das imagens fornecidas.
- [ ] Informar arquivo/frame Figma, caso exista, ou aprovar os tokens do briefing.

## Canais comerciais

- [ ] Informar e verificar o telefone comercial (`phone`).
- [ ] Informar e testar o WhatsApp comercial (`whatsapp`), no formato 55 + DDD + número, somente dígitos.
- [ ] Confirmar que a conta recebe mensagens; a validação de formato não comprova titularidade.
- [ ] Informar a URL HTTPS do perfil de Instagram autorizado (`instagram`).
- [ ] Confirmar o endereço completo (`address`).
- [ ] Confirmar dias e horários de atendimento (`hours`).
- [ ] Somente após validar o endereço, aprovar a URL de incorporação do mapa (`mapEmbedUrl`).

## SEO e publicação

- [ ] Aprovar título e descrição institucionais (`seo.title`, `seo.description`).
- [ ] Fornecer imagem social autorizada (`seo.image`).
- [ ] Confirmar domínio/URL pública definitiva (`seo.siteUrl`) antes de publicar sitemap e URLs canônicas.
- [ ] Autorizar a apresentação oficial do site antes de alterar `demoMode` para `false`.
- [ ] Revisar todos os dados visíveis antes de permitir indexação em robots/meta tags.
- [ ] Confirmar a integração nativa Lovable → GitHub e sua sincronização em `main`.
- [ ] Confirmar a execução verde de CI no GitHub; arquivo de workflow não equivale a execução.
- [ ] Autorizar acesso ao repositório na Render e confirmar plano gratuito/custos no painel antes de publicar.
- [ ] Aplicar o Blueprint e registrar a URL pública somente depois de um deploy concluído.
- [ ] Testar a URL pública em 360, 768, 1024 e 1440px, sem cortes ou sobreposições.
- [ ] Testar todas as âncoras, sidebar, menu mobile (teclado, Escape, overlay, focus trap e retorno de foco) e links reais.
- [ ] Rodar Lighthouse mobile na URL pública e registrar notas, data e condições no README; meta ≥ 90 ou justificativa.
- [ ] Confirmar que os textos demonstrativos não foram publicados como fatos comerciais.

Nenhum preço, prazo, garantia, certificação, avaliação, número de clientes ou tempo de experiência foi fornecido. Esses dados não são necessários para este MVP e só devem ser adicionados com confirmação expressa.
